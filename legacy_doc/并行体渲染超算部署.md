# iGameVis 并行体绘制 —— 超算前后端分离部署指南（阶段 6）

> 版本：v1.0
> 配套实现：`Examples/Rendering/ParallelVolumeServer.h`（后端 C/S 渲染循环）、
> `Examples/Rendering/ParallelVolumeClient.cpp`（前端交互窗口）、
> `Examples/Rendering/ParallelVolumeProtocol.h`（C/S 协议 + 跨平台 socket）。
> 参考：`C:\Projects\TestPVolumeRender\TestPVolumeRender\UnifiedVersion`（MiniPVServer / MiniPVClient / scripts）。

---

## 1. 目标与架构

阶段 6 把并行体绘制拆成「**渲染后端（服务器）**」与「**交互前端（客户端）**」两部分，对标
MiniPVServer / MiniPVClient：

```
超算计算节点（MPI 多 rank，无 GPU、无显示器）          登录节点 / 本地机器（有显示器）
┌───────────────────────────────────────────┐        ┌─────────────────────────────┐
│ testParallelVolumeRendering                │  TCP   │ testParallelVolumeClient     │
│   --cpu --server --port 11111              │ <────> │   <host> <port>             │
│                                            │  帧↓   │   GLFW 窗口显示合成图        │
│ rank0: 监听端口、收命令、发合成图            │  命令↑ │   左键旋转 / 滚轮缩放        │
│ 其余 rank: 无头渲染自己超块 + MPI 合成       │        │   左下角 colorbar + fps     │
└───────────────────────────────────────────┘        └─────────────────────────────┘
```

- **后端**（`testParallelVolumeRendering --cpu --server`）：跑在计算节点，CPU 光线步进体渲染
  天然无头（不依赖 OpenGL/显示器），MPI 分发 + 合成，rank0 用 TCP 把合成图流式回传给前端，
  并接收前端的增量交互命令（`INTERACT <dAzimRad> <dElevRad> <zoom> <flag>`）。
- **前端**（`testParallelVolumeClient`）：跑在登录节点/本地机器，只做「显示 + 输入」，复用
  阶段 5 的 GLFW 交互窗口（colorbar、左键旋转、滚轮缩放、拖动期间 fps），**不依赖 MPI**。
- **关键点**：超算上**只需要编译后端这一个可执行程序**；前端在本地/登录节点编译（它只是
  GLFW 显示 + socket 客户端）。

## 4. 轻量化策略（“剥离”做了什么）

1. **关闭全部可选模块**（在精简 `CMakeLists.txt` 里固化）：
   `ENABLE_CGNS_MODULE=OFF`（去掉 HDF5）、`ENABLE_NASTRAN_MODULE=OFF`、`ENABLE_LIBTORCH_MODULE=OFF`
   （去掉 CUDA/Torch）、`ENABLE_GPSCUDA_MODULE=OFF`（去掉 CUDA/CMakeGPS）、`ENABLE_QT_MODULE=OFF`
   （去掉 Qt 主程序与 GUI）、`ENABLE_WASM=OFF`、`FFMPEG`/`AbqSDK` 找不到即跳过。
2. **不构建全量 Examples**：精简 `Examples/CMakeLists.txt` 只编译 2 个目标，且**不再 `find_package(HDF5)`**
   （CGNS 关闭后核心库本就不需要 HDF5）。
3. **不安装**：`CORE_MODULE_INSTALL=OFF`，跳过 `iGameCoreInstall.cmake` 的安装逻辑。
4. **只复制最小目录**（§2 列表），把 `ThirdParty` 从 ~450MB 降到 ~45MB。

**结果**：超算构建树只包含 iGameCore + 12 个小型第三方库 + 2 个示例目标 + MPI，无 Qt/Torch/CUDA/HDF5/FFMPEG。

> 说明：iGameCore 内部是 `file(GLOB_RECURSE *.h *.cpp)` 单库，仍会编译渲染相关的 OpenGL 封装，
> 因此 glad/glfw 仍需链接（见 §7）。若想进一步做到“完全不链接 GL”，需要把 iGameCore 拆库、只编译
> CPU 后端依赖的子集（工作量与风险较大，留作后续优化，当前不做）。

## 5. 一键打包（在本地开发机执行，产出可上传到超算的目录）

在 iGameVis 仓库根目录执行（需要 `rsync`，Linux/macOS 或 WSL；Windows 下可用 Git Bash）：

```bash
bash Script/pvrender_deploy/package.sh /path/to/iGameVis_Stable_Branch /path/to/pvrender_deploy
```

脚本会：
1. 用 `rsync` 复制 §2 列出的最小目录与 5 个示例文件；
2. 写入精简 `CMakeLists.txt`（顶层）、`ThirdParty/CMakeLists.txt`、`Examples/CMakeLists.txt`；
3. 写入 `build.slurm` / `run_server.slurm` / `start_client.sh`；
4. 打印上传与构建命令。

产出目录结构：

```
pvrender_deploy/
├── CMakeLists.txt            # 精简顶层构建（可选模块全关）
├── iGameCore/                # 核心库（整目录）
├── ThirdParty/               # 仅 12 个子目录 + 精简 CMakeLists
├── Cmake/                    # FindAbqSDK / FindFFMPEG / DeployExampleRuntime
├── Examples/
│   ├── CMakeLists.txt        # 只编译 testParallelVolumeRendering + testParallelVolumeClient
│   └── Rendering/            # 5 个并行体绘制源文件
├── build.slurm               # 超算编译脚本（sbatch）
├── run_server.slurm          # 启动后端（srun，多 rank，--server）
└── start_client.sh           # 启动前端（登录节点）
```

## 6. 编译与运行

### 6.1 上传 + 编译（超算登录节点）

```bash
# 上传（二选一）
rsync -avz pvrender_deploy/ <user>@<login>:/fs2/home/<user>/pvrender_deploy/
scp -r   pvrender_deploy   <user>@<login>:/fs2/home/<user>/

# 提交编译
ssh <user>@<login> 'cd /fs2/home/<user>/pvrender_deploy && sbatch build.slurm'
```

`build.slurm` 产出两个可执行文件：
- `build/testParallelVolumeRendering`（后端，MPI）
- `build/testParallelVolumeClient`（前端）

> 前端也可以在**本地 Windows** 用现有 `pvr` 预设编译（`Examples/CMakeLists.txt` 已注册
> `testParallelVolumeClient`），无需在超算编译前端。

### 6.2 启动后端（超算，多 rank）

```bash
sbatch run_server.slurm
```

`run_server.slurm` 核心命令（按需改 `DATA`/`PARAMETER`/`PORT`）：

```bash
srun --cpu-bind=cores --distribution=block:block \
    ./testParallelVolumeRendering \
        -i "$DATA" -t $TIMESTEP --resample 64 --cpu \
        --field "$PARAMETER" \
        --server --port $PORT
```

> `--field` 直接指定字段名，跳过 rank0 的交互式 stdin 字段选择（srun 批处理没有 stdin，必须指定）。
> 字段名需与数据里的点/单元标量或向量名精确匹配（带空格要加引号）。

rank0 打印 `[server] rank 0 listening on port 11111` 并阻塞等待前端连接。

### 6.3 启动前端（登录节点，或本地经端口转发）

```bash
# 登录节点（有显示器/X 转发时）
bash start_client.sh <server_node> 11111

# 或本地机器经 SSH 端口转发连到计算节点
ssh -N -L 11111:<server_node>:11111 <user>@<login> &
testParallelVolumeClient 127.0.0.1 11111
```

前端窗口：左键拖动旋转、滚轮缩放、左下角 colorbar（含全局标量范围）、拖动期间显示 fps。

## 7. 已知注意事项（务必阅读）

1. **字段选择**：批处理（`srun`）下后端没有 stdin，**必须用 `--field <name>` 指定字段**，
   否则 rank0 的 `std::getline(std::cin)` 会立即读到 EOF、后端直接退出。
2. **glfw 依赖 X11/Wayland 开发库**：iGameCore 单库会编译/链接 glad+glfw，glfw 在 Linux 构建时
   需要 X11（或 Wayland）开发头。集群通常自带，或像参考实现一样 `module load qt`（Qt 附带 X11 依赖）。
   若 configure 报 `glfw ... requires X11`，请加载 Qt module 或安装 `libx11-dev libxrandr-dev
   libxinerama-dev libxcursor-dev libxi-dev`。
3. **目录大小写**：仓库根目录是 `Cmake/`（大写 C）。精简顶层 `CMakeLists.txt` 已统一用大写 `Cmake/`
   写入 `CMAKE_MODULE_PATH`，避免原始根 `CMakeLists.txt` 里小写 `cmake` 在 Linux 上找不到路径的问题。
4. **前端连接网络**：计算节点通常不能被登录节点/本地直接路由，跨节点需用 SSH 端口转发
   （`ssh -L`）或保证前端与 rank0 所在计算节点在同一可达网段（参考实现直接填计算节点 hostname）。
5. **当前帧是 raw RGBA8**（无压缩），1024×1024 ≈ 4MB/帧。若 compute→login 链路带宽不足，可后续
   仿照 MiniPVServer 改 PNG 压缩（协议头 `codec` 字段已预留，仅需在 `ParallelVolumeProtocol.h` 的
   `SendFrame`/`ParseFrame` 里加 PNG 编码/解码分支）。
6. **非 2 幂 rank / 分块约束**：沿用阶段 2 的 `iGameVolumeDistributor`，要求 `进程数 ≤ 分块数`，
   且分块能构成完整规则网格；不满足时所有 rank 一致报错退出（避免空块死锁）。
7. **`iGameCore/CMakeLists.txt` 里残留的 `Qt5_DIR`（`D:/Qt/...` Windows 路径）是无害的**：Qt 已关闭，
   该变量不会被使用，忽略即可。
