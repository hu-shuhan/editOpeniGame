# Subdivide 单元属性丢失回归用例

BUG：PR #147 的 SubdivideOnce 只调用 InterpolatePointAttributes，新输出没有 CellData，输入上的区域编号和单元标量在细分后消失。修复提交：待提交。

本用例使用一个由两个三角形构成的单位正方形，两个父面具有不同的 RegionId 和 CellValue。属性使用 float，以单独验证单元属性保留，避免混入整数类型转换问题。两个面共享对角边，额外检查中点是否复用；PointValue = x + y 作为点插值对照。

## 操作

1. 加载 input.vtk。确认输入有 4 个点、2 个面，模型树中有单元属性 RegionId 和 CellValue，以及点属性 PointValue。
2. 对输入执行「三角面细分 (Subdivide)」，次数设置为 1。
3. 检查新结果：应有 9 个点、8 个三角面，并保留两个单元属性，每个数组有 8 个元组。
4. 选择结果的单元属性 RegionId 着色：正方形对角线两侧应分别为 11 和 22；每侧四个子面值相同。CellValue 对应为 100 和 200。
5. 可加载 expected_level1.vtk 作为参考模型，分别显示并比较。参考文件不是 filter 实际输出。

## 预期

按 PR 当前的面输出顺序：

| 输出面 ID | 来源输入面 | RegionId | CellValue |
| --- | --- | --- | --- |
| 0、1、2、3 | 0（0,1,2） | 11 | 100 |
| 4、5、6、7 | 1（0,2,3） | 22 | 200 |

PointValue 应为 `[0,1,2,1,1,0.5,1.5,0.5,1.5]`，长度为 9。输入的坐标、拓扑和属性不应被修改。

如果以后调整面排列顺序，应按几何对应关系检查父面属性，不要求固定 ID。再次测试细分次数 2 时，应有 25 个点、32 个面，RegionId=11 和 RegionId=22 各占 16 个面。

## 失败判据与验证范围

任何单元数组消失、元组数不是输出面数、子面值与父面不一致，均算失败。只有点数和面数正确不能算通过。
